# Auditoría de recursos de la WEB pública

Fecha: 13 de octubre de 2026. Repositorio: SanLean17/SanLean17.github.io. Alcance: páginas públicas en la raíz, sus dependencias CSS/JS, datos y assets. Se excluyen Usuario, OBS y Supabase privados. No es un dictamen jurídico ni una autorización de los titulares.

## Método y límites

Se siguieron los scripts, estilos, imágenes y JSON de las diez páginas públicas existentes, incluidas cargas dinámicas y estilos responsive. Se contrastaron los árboles públicos de 3stadt y DanteASC4 con hashes Git de imágenes, datos y código local. El [manifiesto reproducible](public-asset-matches.json) registra los 321 archivos coincidentes y las revisiones remotas; una coincidencia demuestra igualdad de bytes, no quién descargó primero el archivo ni la cadena de derechos. Cero coincidencias tampoco descarta una imagen renombrada, recomprimida o editada.

El historial local disponible comienza con una instantánea que ya contiene los recursos, sin documentos de adquisición ni autorizaciones individuales. No se puede reconstruir con certeza su procedencia histórica. No se encontraron bibliotecas de TierMaker ni cargas de servicios de NightLight en el recorrido público. No se detectó código idéntico por archivo completo en los dos repositorios cotejados; esto no prueba ausencia de fragmentos adaptados. No se declara autoría propia de un recurso solo porque esté guardado en el repositorio.

## Datos y código

- `data/perks-killer.json`: 146 entradas, incluido SLOT VACÍO; 145 perks reales. Frente a la localización española actual de 3stadt coinciden 142 claves y 95 nombres.
- `data/perks-survivor.json`: 177 entradas, incluido SLOT VACÍO; 176 perks reales. Coinciden 176 claves y 140 nombres. Estas correspondencias sustentan relación con el conjunto de datos, pero no una cadena de adquisición única.
- `data/killers.json` y `data/perk-conflicts.json` están en el recorrido público. `js/tierlist-dbd.js` conserva los listados locales de personajes; no consume una API de DBD. Los datos de juego no pasan a ser propiedad de SanLean por estar en JSON.
- `data/survivors.json` existe, pero la Tierlist actual utiliza su listado local en JavaScript. No confundir archivo existente con petición activa. Otros JSON privados/de cartas quedan fuera del alcance.
- No se introdujo librería de terceros para el arrastre ni para el formulario. Los engranajes y SVG inline existentes no requieren una biblioteca externa identificada. El namespace SVG de W3C no es un servicio descargado.

## Contacto y activación

El hosting público es estático (GitHub Pages). No se encontró un transporte de correo reutilizable; las funciones Supabase existentes tienen fines privados diferentes. Se implementó FormSubmit sin credenciales de Gmail, con validación, texto obligatorio, bloqueo de envíos simultáneos, timeout, honeypot y errores que conservan el texto. La segunda pasada retiró el correo directo y la explicación del proveedor de la interfaz; el transporte AJAX no cambió.

El propietario autorizó expresamente enviar dirección y prueba a FormSubmit, confirmó el enlace de activación y el proveedor respondió `success: true` a la prueba real. Esto acredita aceptación por el servicio, no lectura ni llegada a bandeja principal; revisar spam si hiciera falta. Los tests de estados usan respuestas simuladas y no envían correos.

Para desactivar el transporte: cambiar `data-contact-enabled` a `false` en `contacto.html`; el formulario mostrará un error de indisponibilidad sin enlace de correo. No agregar tokens al frontend. Para migrar de servicio, reemplazar el endpoint y revisar nuevamente términos y límites.

Pruebas locales aprobadas: Chrome y Edge con movimientos de mouse, botón sostenido, rueda y drop en las cinco categorías; scroll progresivo y detención al soltar/cancelar; cinco colecciones táctiles a 320/390/740 px; doce páginas, footer y contacto a 320/390/740/1024/1440 px; validación, espera, doble envío, éxito y errores simulados del formulario; regresión de giros de ruletas, SLOT VACÍO y tooltips. Son pruebas de navegador automatizadas con eventos de entrada, no una sesión física con el mouse del usuario. No se modificaron archivos de Usuario ni el CSS/JS de su sistema visual.
